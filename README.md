# AutoCAD MCP Bridge

Управление запущенным AutoCAD 2025–2027 из ИИ-ассистента: Claude Desktop, Claude Code, Codex
(и любого MCP-клиента). План развития и журнал решений — [PLAN.md](PLAN.md).

```
ИИ-клиент ──stdio/MCP──► dotnet acad_mcp_server.dll ──HTTP JSON──► AcadMcpBridge.dll (внутри acad.exe)
                         (server\AcadMcpServer)       localhost:8766   (src\)
```

MCP-сервер — небольшая библиотека .NET без зависимостей; клиент запускает её через `dotnet.exe`
(среда .NET ставится вместе с AutoCAD 2025–2027). Отдельного exe нет намеренно: на управляемых
компьютерах неподписанные exe в папках пользователя часто блокируются, а `dotnet.exe` подписан.
До версии 0.2.x сервер был на Python. Независим от Navisworks MCP: свой порт (8766), бандл и
сервер — оба моста работают одновременно.

## Версии

| AutoCAD | Сборка | .NET |
|---|---|---|
| 2025, 2026 | `Contents\R25` | net8.0 (работает и на .NET 10 после обновлений 2025/2026) |
| 2027 | `Contents\R26` | net10.0 |

## Что умеет (v0.7.0)

59 инструментов: Claude читает чертёж, видит его (снимок вида), рисует и правит объекты, ставит размеры
и мультивыноски, работает со слоями, блоками, таблицами и стилями оформления, открывает, сохраняет и
печатает чертежи в PDF, подключает внешние ссылки, чистит чертёж и переносит стандарты из шаблонов.
Если пользователь разрешит, Claude выполняет команды AutoCAD и выражения AutoLISP.
Все инструменты работают с **активным** чертежом; переключиться на другой — `set_active_document`.
`batch_run` прогоняет те же инструменты по папке чертежей без окна AutoCAD (консольный AutoCAD).

Примеры запросов:
- «Что за чертёж открыт? Какие слои, блоки, листы, внешние ссылки?»
- «Найди все блоки PUMP* на слое E-POWER и выгрузи их атрибуты таблицей»
- «Прочитай таблицу на листе A1 и проверь сумму в столбце мощностей»
- «Заполни выделенные ячейки таблицы этими значениями», «Создай спецификацию по атрибутам блоков»
- «Переложи все тексты со слоя 0 на слой TEXT и сделай их синими» (Claude сначала покажет, что будет затронуто)
- «Начерти прямоугольник 600×400 со скруглёнными углами и подпиши его»
- «Покажи, как выглядит лист A1» (Claude получает картинку и может проверить, что нарисовал)
- «Создай размерный стиль под масштаб 1:50 и проставь размеры стен», «Подпиши насосы выносками»
- «Открой все чертежи из папки, напечатай листы в один PDF и закрой»
- «Перенеси слои и стили из нашего шаблона, удали неиспользуемое и сохрани как DWG 2013»
- «Выполни OVERKILL для всего чертежа», «Загрузи мой LISP и посчитай им площади» (нужно разрешение команд)
- «Проверь все чертежи в папке проекта: на каких нет слоя E-POWER и где ошибки аудита»
- «Во всех чертежах папки поменяй атрибут REV на C и сохрани копии в папку Out», «Напечатай всю папку в PDF»

### Чтение (ничего не меняют)

| Инструмент | Что делает |
|---|---|
| `health_check` | Версии плагина, AutoCAD, .NET, порт. Отвечает, даже если AutoCAD занят |
| `get_document_info` | Активный чертёж: имя, путь, несохранённые изменения, единицы, границы, текущий слой и лист, счётчики объектов |
| `list_documents` | Открытые чертежи, какой активный |
| `list_layers` | Слои: цвет, тип и вес линий, вкл / заморожен / заблокирован / печать, текущий, число объектов |
| `list_blocks` | Определения блоков: атрибуты (тег, подсказка, значение по умолчанию), число вставок (с динблоками) |
| `list_layouts` | Модель и листы: объекты, видовые экраны, устройство печати, формат |
| `list_xrefs` | Внешние ссылки: путь, состояние (загружена, не найдена…) |
| `list_styles` | Стили текста, размеров, таблиц, мультивыносок, типы линий |
| `get_system_variable` | Значения системных переменных |
| `find_entities` | Поиск объектов: тип, слой, имя блока, рамка (внутри / пересекает), пространство или лист, **текст** (тексты, MText, атрибуты, размеры, ячейки таблиц). Маски `*` и `?`, постранично |
| `get_entity_properties` | Полные свойства до 100 объектов: геометрия, тексты, атрибуты и свойства динблоков, XData |
| `get_selection` | Что пользователь выделил в AutoCAD («вот эти объекты») |
| `get_table` | Содержимое таблицы AutoCAD: ячейки (текст как на экране / с кодами / типизированные значения), объединения, формулы, заблокированные ячейки, блоки в ячейках, связи с Excel, выделенные ячейки; большие таблицы — частями |
| `extract_block_attributes` | Атрибуты блоков таблицей: строка на вставку, столбец на тег |

| `create_mleader` | Мультивыноска с текстом: точки от стрелки к надписи, несколько стрелок к одной надписи, стиль, высота текста |

Новые объекты по умолчанию получают цвет, тип и вес линий «ПоСлою»; новый слой — тип линий Continuous.

| `modify_dimension` | Размеры: замена текста, стиль, высота текста, стрелки, точность, масштаб, размещение и положение текста, сброс переопределений |

| `delete_entities` | Удалить |
| `update_block_attributes` | Значения атрибутов: одно для многих блоков или разные для каждого |
| `set_table_cells` | Запись в ячейки таблицы: список ячеек или блок значений, от выделенных ячеек, с дописыванием строк; текст, числа, `=формулы` |
| `modify_table` | Строки и столбцы (вставить / удалить), объединить / разъединить ячейки, ширина столбца, высота строки |

| `set_selection` | Выделить объекты в AutoCAD, чтобы показать их пользователю |
| `set_system_variable` | Изменить системную переменную |
| `undo` | Отменить последние изменения, сделанные Claude |

### Файлы, печать, ссылки

| Инструмент | Что делает |
|---|---|
| `new_document`, `open_document` | Новый чертёж по шаблону; открыть DWG/DXF/DWT (можно только для чтения). Чертёж становится активным |
| `set_active_document`, `close_document` | Переключить активный чертёж; закрыть (с несохранёнными изменениями — только с `save` или `discard_changes`) |
| `save_document`, `save_as` | Сохранить; сохранить как DWG/DXF 2018…2000 (существующий файл — только с `overwrite`) |
| `plot_to_pdf` | Листы (или все) в один многостраничный PDF или по файлу на лист; модель — всё или рамка, вписать или масштаб |
| `attach_xref`, `manage_xrefs` | Подключить внешнюю ссылку (вставка / наложение, относительный путь); обновить, выгрузить, удалить, внедрить, сменить путь |
| `purge` | Удалить неиспользуемые слои, типы линий, блоки, стили; по умолчанию только показывает, что удалит |
| `audit` | Проверка чертежа (с исправлением по запросу) и отчёт |
| `import_from_drawing` | Слои, типы линий, стили, блоки из другого DWG или шаблона; существующие не трогает (или заменяет по запросу) |

### Команды AutoCAD и AutoLISP (только с разрешения пользователя)

| Инструмент | Что делает |
|---|---|
| `run_command` | Команда AutoCAD с ответами на её запросы (`inputs`); возвращает текст командной строки. Команда, которой не хватило ответов, отменяется, и Claude видит, на каком запросе она остановилась |
| `eval_lisp` | Выражение AutoLISP; значение возвращается как JSON (списки, точки, объекты — как handle) и в записи LISP, плюс то, что напечатал `princ`. Ошибка LISP — сообщением |

По умолчанию **выключены**. Включить: кнопка **Commands** на панели **AI companion** или команда
`MCPCOMMANDS` — после предупреждения (на русском, если AutoCAD русский, иначе на английском) с кнопками
«Все равно разрешить» / «Отказаться»; действует до закрытия AutoCAD, повторное нажатие выключает.
Насовсем — `"allowCommands": true` в `config.json`. Без разрешения оба инструмента отвечают
`commands_disabled` с подсказкой, как включить. Состояние видно в `MCPSTATUS` и `health_check`.

- Не выполняются: `QUIT`, `EXIT`, `CLOSE`, `CLOSEALL`, `SHELL`, `SH`, `NETLOAD`, `APPLOAD`, `ARX`, `VBALOAD`, `VBARUN`.
- На время вызова выключены диалоги (`FILEDIA`, `CMDDIA`), потом возвращаются; если AutoCAD закрылся
  посреди вызова, плагин вернёт их при следующей загрузке.
- В `eval_lisp` отклоняются `command`/`command-s`/`vl-cmdf` (вешают AutoCAD через этот вызов — для команд
  есть `run_command`), функции, ждущие пользователя (`getpoint`, `entsel`, `ssget` без режима …), и
  незакрытые скобки. Бесконечный цикл в LISP заблокирует AutoCAD.
- Каждый вызов — один шаг `undo`.

### Пакетная обработка папок (без окна AutoCAD)

| Инструмент | Что делает |
|---|---|
| `batch_run` | Одни и те же шаги (вызовы инструментов выше, с теми же аргументами) по папке DWG (`folder`, `pattern`, `recursive`) или списку файлов. На каждый чертёж — свой консольный AutoCAD (`AcCoreConsole`), несколько параллельно; открытый AutoCAD не нужен и не занимается |
| `batch_status` | Ход длинного пакета, отчёт частями, отмена; без `job_id` — список пакетов сеанса |

- **Скорость:** ~3–4 с на чертёж плюс сами шаги; параллельно — половина ядер процессора, не больше 4
  (`parallel` до 8). `batch_run` ждёт до 10 минут, дальше возвращает `job_id` для `batch_status`.
- **Чтение** (`get_*`, `list_*`, `find_entities`, атрибуты, таблицы, `audit` без исправлений, всё с
  `dry_run: true`) и **печать в PDF**: чертежи открываются только для чтения и не сохраняются. Можно читать и
  чертёж, открытый сейчас в AutoCAD.
- **Изменения** — только когда пользователь выбрал, куда сохранять (если не сказал — Claude спросит):
  - `save: "copy"` + `output_folder` — изменённые чертежи сохраняются туда, подпапки сохраняются, исходники
    не трогаются; существующие файлы заменяются только с `overwrite: true`;
  - `save: "in_place"` + `confirm: true` — поверх исходника, предыдущая версия остаётся рядом как `.bak`.

  Сохраняется только реально изменённый чертёж, в своей версии DWG; после ошибки шага файл не сохраняется
  (с `continue_on_error` — сохраняется с успешными изменениями). Файлы «только для чтения» и занятые (открыты
  в AutoCAD или другим пользователем) пропускаются с пометкой в отчёте.
- **Печать:** `path` у `plot_to_pdf` в пакете — папка; каждый чертёж печатается в `<имя>.pdf` (с
  `separate_files` — `<имя>-<лист>.pdf`), подпапки сохраняются.
- **Команды и AutoLISP** в пакете — только при `"allowCommands": true` в `config.json` (кнопка **Commands**
  относится к сеансу AutoCAD и на пакеты не действует). На время команды выключена объектная привязка; команду,
  которой не хватило ответов, консоль завершает Enter (Esc там нет).
- Не работают в пакете: открытие/сохранение/закрытие чертежей, вид и снимки, выбор, `undo`.
- Консоли работают в собственном профиле AutoCAD (`%LOCALAPPDATA%\AcadMcpBridge\console\<год>`): настройки
  пользователя не меняются. Первый запуск в новом профиле дольше (профиль создаётся), консоли идут по одной.

### Безопасность изменений

- **Один вызов — один шаг отмены.** `undo` откатывает только изменения Claude: если пользователь
  после них сам выполнил команду в AutoCAD, `undo` откажется и предложит UNDO в AutoCAD.
- **Массовые изменения по фильтру** выполняются только с `confirm: true`; `dry_run: true` показывает,
  сколько и каких объектов будет затронуто, ничего не меняя.
- **Заблокированные слои:** если хоть один объект на заблокированном слое — отказ, ничего не меняется.
- **Заблокированные ячейки таблиц** (в том числе связанные с Excel) не записываются, обхода нет:
  Claude называет ячейки и просит снять блокировку в AutoCAD.
- **Файлы не теряются молча:** чертёж с несохранёнными изменениями закрывается только с явным
  `save` или `discard_changes`; существующие DWG и PDF перезаписываются только с `overwrite: true`;
  занятый файл не открывается на запись (AutoCAD задал бы вопрос и заблокировал мост).
- Пока в AutoCAD идёт команда или открыт диалог, изменения не выполняются (`busy`); чертёж только
  для чтения не меняется.
- Команды AutoCAD и AutoLISP — только после явного разрешения пользователя (см. выше).
- **Пакеты** меняют файлы на диске только после выбора пользователя: копии в отдельную папку или поверх с
  `.bak` (подтверждение `confirm: true`); занятые и защищённые от записи файлы не трогаются.
- Если другая программа передала чертежу команду через COM `SendCommand`, AutoCAD перестаёт запускать в
  нём команды моста; мост сам переключается на другой открытый чертёж и обратно, и вызов проходит.
- Мост слушает только `localhost` и включается лишь командой `MCPSTART`.

### Ограничения

- Только AutoCAD 2025–2027 (не LT), только активный чертёж (кроме `batch_run`).
- Размеры: только линейные и выровненные.
- Пакеты: не больше 2000 файлов и 50 шагов; задания живут, пока работает MCP-сервер (после перезапуска
  клиента `batch_status` их не знает); маска файлов — `*` и `?` (без `[abc]`).
- Печать — только в PDF («DWG To PDF.pc3»). Лист, который ни разу не открывали, при печати создаёт свой
  видовой экран, как при щелчке по вкладке.
- Исправления `audit` (`fix: true`) нельзя отменить через `undo`; у несохранённого чертежа нет отчёта аудита.
- Создавать динамические блоки нельзя — только вставлять готовые и менять их свойства.
- Высота строк таблицы при уменьшении текста не уменьшается (это минимальная высота в AutoCAD).
- «Таблицы» из линий и текстов (не объект AutoCAD Table) не распознаются — см. PLAN.md, раздел 9.

## Установка у пользователя

Нужно: AutoCAD 2025–2027 (не LT) и ИИ-клиент (Claude Desktop, Claude Code или Codex). Python,
интернет и права администратора не нужны.

1. Распакуйте `AutoCAD_MCP_<версия>.zip` в любую папку (не запускайте из архива).
2. Закройте AutoCAD и запустите `INSTALL.BAT`.
3. Выберите язык установщика — вопрос на английском: `1` — English, `2` — Русский.
   Дальше все сообщения на выбранном языке.
4. Установщик покажет найденные версии AutoCAD и спросит год версии (`2026`), `A` — все
   поддерживаемые (2025–2027), `U` — удалить, `Q` — выход.
5. Установщик найдёт установленные ИИ-клиенты и для каждого спросит, подключить ли сервер
   `autocad` (`Y`/`N`). Перезапустите подключённые клиенты.
6. Запустите AutoCAD и нажмите **Start** на панели **AI companion** вкладки «Главная» (или `MCPSTART`).

Без вопросов: `INSTALL.BAT 2026`, `INSTALL.BAT A`, `INSTALL.BAT U`; язык — вторым параметром,
`INSTALL.BAT 2026 RU` (по умолчанию `EN`). В этом режиме сервер подключается ко всем найденным клиентам.

Что делает установщик:

| Шаг | Куда |
|---|---|
| Плагин и MCP-сервер (`AcadMcpBridge.bundle.zip` распаковывается) | `%APPDATA%\Autodesk\ApplicationPlugins\AcadMcpBridge.bundle` (сервер — `Contents\Server\acad_mcp_server.dll`) |
| Claude Desktop — если есть `%APPDATA%\Claude` | `claude_desktop_config.json`, `mcpServers.autocad` |
| Codex (CLI, расширение IDE, приложение) — если есть `%USERPROFILE%\.codex` (или `CODEX_HOME`) либо команда `codex` | `config.toml`, таблица `[mcp_servers.autocad]` |
| Claude Code — если есть команда `claude` | `claude mcp add --scope user autocad …` |

- Перед первой правкой конфига клиента рядом сохраняется копия `<файл>.bak-autocad`; меняется
  только запись `autocad`, другие серверы (`navisworks`, `Revit` …) и настройки не трогаются.
- Клиент, в котором `autocad` уже был (от прежней версии), обновляется без вопроса.
- **Обновление с 0.2.x (Python):** окружение `%LOCALAPPDATA%\AcadMcpBridge\venv` удаляется, файлы
  Python-сервера из бандла тоже; запись `autocad` в Claude Desktop переводится на новый сервер.
  Сам Python не удаляется. Запись в Claude Code, сделанную вручную, обновите командой ниже.
- Подключить клиент позже: `"<dotnet.exe>" "<бандл>\Contents\Server\acad_mcp_server.dll" --register claude-desktop|claude-code|codex`
  (установщик печатает готовые команды), отключить — `--unregister`.
- `PackageContents.xml` собирается так, что плагин загружается только в выбранных версиях;
  повторный запуск с другой версией добавляет её (список — `versions.txt` в бандле).
- Версии до 2025 отклоняются («не поддерживается»), новее 2027 — «нужен новый выпуск».
- Если выбранная версия не найдена в реестре (`HKLM\SOFTWARE\Autodesk\AutoCAD\R<серия>`) — предупреждает и спрашивает.
- Не работает при запущенном `acad.exe` (DLL была бы занята).
- `U` удаляет плагин, запись `autocad` из всех клиентов и старое окружение Python; настройки и журнал
  (`%LOCALAPPDATA%\AcadMcpBridge`) — по отдельному вопросу.

## Installation (English)

1. Unpack `AutoCAD_MCP_<version>.zip` to any folder, close AutoCAD and run `INSTALL.BAT`.
2. Choose the language (`1` English, `2` Russian), then the AutoCAD year (`2026`), `A` for all
   supported versions (2025–2027), `U` to uninstall or `Q` to quit.
3. The installer finds Claude Desktop, Claude Code and Codex and offers to connect the `autocad`
   server to each. Restart the connected clients. No Python is needed; the Python environment of
   versions up to 0.2.x is removed.
4. Start AutoCAD and press **Start** on the **AI companion** panel (Home tab), or type `MCPSTART`.

Unattended: `INSTALL.BAT 2026 EN`, `INSTALL.BAT A`, `INSTALL.BAT U`.

## Сборка (разработка)

```powershell
.\Build-Package.ps1           # собрать R25 + R26 -> release\AutoCAD_MCP_<версия>\ и release\AutoCAD_MCP_<версия>.zip
.\Build-Package.ps1 -Deploy   # то же + установить здесь: INSTALL.BAT A без подключения клиентов
```

В `release\` копятся архивы всех версий (`AutoCAD_MCP_<версия>.zip`); распакованная папка — только текущей.
Описание релиза для пользователей (RU + EN): исходник `installer\RELEASE.md`, при сборке кладётся в `release\RELEASE.md`
и в архив.

Версия — одна, `<Version>` в `src\AcadMcpBridge.csproj`; `PluginVersion` (C#) должна совпадать,
иначе сборка остановится; MCP-сервер публикуется с той же версией. Исходники установщика — папка
`installer\` (`INSTALL.BAT`, части манифеста `PackageContents\`, `RELEASE.md`).
Новая версия AutoCAD: строка `SERIES_<год>` и `MAX_YEAR` в `INSTALL.BAT`, файл
`installer\PackageContents\R<серия>.xml`, при новой серии — сборка в `Build-Package.ps1` и csproj.

**MCP-сервер** (`server\AcadMcpServer`, net8.0 с переходом на .NET 10, без NuGet-пакетов):
`tools.json` — имена, описания и схемы параметров всех инструментов (то, что видит модель);
новый инструмент = обработчик в плагине + запись в `tools.json`. Сервер пересылает вызов на маршрут
моста с тем же именем.

Python в проекте нужен только тестам (`.venv`: пакет `mcp` как MCP-клиент, `pywin32` для тестового чертежа):

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install mcp -r tests\requirements-dev.txt
```

## Запуск

В AutoCAD: **`MCPSTART`** — включить мост, `MCPSTATUS` — состояние, `MCPSTOP` — выключить.

То же — кнопками на ленте: вкладка **Главная (Home)** → панель **AI companion** →
**Start** / **Stop** / **Status**, переключатель **Commands** (разрешить команды и AutoLISP, `MCPCOMMANDS`). Панель добавляет сам плагин при загрузке (API ленты), файлы
настройки AutoCAD (CUIx) не меняются; после удаления плагина панель исчезает. Если в рабочем
пространстве нет вкладки «Главная», панель появляется на своей вкладке «AI companion».
Иконки — `src\Resources\McpStart|McpStop|McpStatus|McpCommands_16|32.png`, рисуются `tools\Make-Icons.ps1`
(можно заменить своими PNG тех же имён и размеров).
Проверка без MCP-клиента: `Invoke-RestMethod http://localhost:8766/health`.

## Настройки

`%LOCALAPPDATA%\AcadMcpBridge\config.json` — создаётся установщиком со значениями по умолчанию (существующий
файл не меняется); без файла плагин работает с теми же значениями:

```json
{ "port": 8766, "token": "", "requestTimeoutSeconds": 30, "allowCommands": false }
```

`allowCommands: true` разрешает `run_command` / `eval_lisp` сразу при загрузке, без кнопки и предупреждения.

Если меняете порт или задаёте токен — те же значения передайте MCP-серверу через
переменные `ACAD_MCP_PORT` и `ACAD_MCP_TOKEN`. Лог: `%LOCALAPPDATA%\AcadMcpBridge\log.txt`.

## Тесты

```powershell
.venv\Scripts\python.exe -m pip install -r tests\requirements-dev.txt   # один раз: pywin32 для тестового чертежа
```

Изменяющие проверки выполняются **только в новом безымянном пустом чертеже**; в любом другом
выполняются лишь проверки чтения. Тестовый чертёж (слои, тексты, блок с атрибутом, две таблицы)
строится через COM AutoCAD (`tests\fixture.py`), независимо от проверяемых инструментов.
Разделы: `smoke_test.py` (связь, шаги 1–3), `test_edit.py`, `test_draw.py`, `test_tablewrite.py`,
`test_fixes.py`, `test_dynamic.py` (динблок импортируется через ObjectDBX), `test_dims.py`,
`test_styles.py`, `test_mleader.py`, `test_view.py` (вид, листы, снимки), `test_files.py` (документы,
сохранение, PDF, внешние ссылки, очистка, импорт — все файлы во временной папке), `test_commands.py`
(`run_command`, `eval_lisp`, работа после COM `SendCommand`).

Пакетная обработка проверяется без окна AutoCAD (на копиях образца AutoCAD «Architectural - Metric.dwg»
во временной папке):

```powershell
.\tests\Test-BatchConsole.ps1                  # плагин в консоли напрямую (MCPBATCH), 2026 и 2027
.venv\Scripts\python.exe tests\test_batch.py    # batch_run / batch_status через MCP-сервер
```

`test_batch.py` включает команды через свой файл настроек (`ACAD_MCP_CONFIG`), не трогая `config.json`
пользователя; если запущен AutoCAD с мостом, дополнительно проверяет чтение открытого в нём чертежа.
`AcadSession.ps1 -Start` разрешает команды только этому сеансу AutoCAD (переменная `ACAD_MCP_ALLOW_COMMANDS=1`,
`config.json` не трогается); с `-NoCommands` проверяется отказ `commands_disabled`.
v0.7.0: 420/420 в AutoCAD 2026 и 2027; с `-NoCommands` — 385/385; `test_batch.py` 99/99 (с запущенным
AutoCAD — 61/61 на версию); `Test-BatchConsole.ps1` 33/33.
